# 10. 3차(복약) 법적 요구사항

> 초안 v0.1 (2026-10-12). 3차 복약 기능을 출시하기 전에 끝낼 법적 요구사항을 모았습니다.
> 출처: 법적 검토 v1(비공개 보관)과 구현 보완 체크리스트의 "3차" 행(C-05, D-03, D-04, P-11, P-12, T-09)과 관련 행(P-01, P-03, R-11, R-32).
> 이 문서는 법률 자문이 아닙니다. 문구와 판단은 출시 전 변호사 확인을 받습니다.
> `[확인 필요: …]`는 3차 설계 때 정할 곳입니다.

## 2. 세부 요구사항과 완료 조건

### LR3-01. 민감정보 동의서 v2와 재동의 (C-05)

- 동의서 v2에 넣을 항목(`docs/policies/동의서_본문.md` 4절에 더함)
  - 받는 정보: 약 이름, 용량, 복용 횟수, 복용 시간, 시작일·종료일, 복용 시점(식전·식후 등), 복용 기록(먹음·건너뜀·시각)
  - 쓰는 곳: 정한 시간 알림, 복용 기록 확인
  - 약봉투 사진: 휴대폰 안에서 글자만 읽고 사진은 바로 지운다. 서버로 보내지 않는다
  - 보관 기간: 철회·탈퇴 때까지
  - 거부 시 불이익: 복약 알림만 쓸 수 없다. 운동·식단 기능은 그대로
- 완료 조건
  - [ ] `documents.json`의 `SENSITIVE` 버전을 올리면 기존 동의자의 `needs_reconsent`가 `true`가 된다
  - [ ] 재동의 전에는 복약 API가 `403 SENSITIVE_CONSENT_REQUIRED`(또는 재동의 전용 코드)를 준다 `[확인 필요: 오류 코드]`
  - [ ] 재동의 화면은 바뀐 부분을 먼저 읽어 준다
  - [ ] 질환·알레르기 동의와 복약 동의를 따로 받을지 정한다. 따로 받으면 거부해도 기존 질환·알레르기 동의는 유지 `[확인 필요: 3차 설계 결정]`

### LR3-02. 약 사진을 서버에 두지 않음 (D-03)

- 설계 ERD의 `MEDICATION.photo` 필드를 서버 모델에서 뺀다.
- 약봉투에는 환자 이름, 병원, 약국, 처방일 같은 제3자·추가 정보가 있다. 기기 안 글자 인식(ML Kit) 후 사진 파일을 바로 지운다.
- 약 사진을 꼭 보여 줘야 하면 기기 안 암호화 영역(SQLCipher 데이터베이스나 앱 전용 암호화 파일)에만 둔다.
- 완료 조건
  - [ ] 서버 API에 이미지 업로드 경로가 없다
  - [ ] 사진 파일이 공용 저장소(갤러리)에 남지 않는다
  - [ ] 인식 결과에서 약 이름·용량·시간만 고르고, 환자 이름·병원·약국은 저장하지 않는다
  - [ ] Data safety의 Photos는 "수집 안 함"을 유지한다

### LR3-03. 복약 데이터 암호화와 삭제 (D-04)

- 복약 테이블(약 이름·용량·시간·복용 기록)을 `EncryptedJSONField` 또는 암호화 컬럼으로 저장한다.
- `sensitive_consent_withdrawn`, `account_withdrawn` 신호에 복약 데이터 삭제 수신자를 붙인다.
- 완료 조건
  - [ ] DB를 직접 열어도 약 이름이 평문으로 보이지 않는다
  - [ ] 민감정보 동의 철회와 탈퇴 테스트에서 복약 데이터가 0건이 된다
  - [ ] 오프라인 대기열(기기)의 복약 기록도 철회·탈퇴 때 지운다
  - [ ] 서버 로그와 오류 기록에 약 이름이 남지 않는다

### LR3-04. 정확한 알람 (P-11)

- `SCHEDULE_EXACT_ALARM`을 선언한다. Android 14 이상 새 설치에서는 기본으로 꺼져 있으므로, 허용 화면으로 안내한다.
- 허용 안내 문구 예: "정한 시간에 정확히 알려 드리려면 알람 권한이 필요해요. 허용하지 않으셔도 몇 분 차이가 있는 알림으로 알려 드려요."
- 거부하면 `setWindow` 등으로 대체 알림을 건다.
- `USE_EXACT_ALARM`은 쓰지 않는다. 복약 알림은 이 권한의 허용 사례로 명시돼 있지 않다.
- 완료 조건
  - [ ] 권한 거부, 권한 회수, 재부팅, 시간대 변경 후에도 알림이 다시 등록된다
  - [ ] 알림 실패를 앱이 알면 사용자에게 알린다(R-11)
  - [ ] 알림 권한(`POST_NOTIFICATIONS`)도 첫 알림 설정 때 이유를 먼저 읽어 주고 요청한다(T-13)

### LR3-05. 전체화면 알림 (P-12)

- 쓸지부터 정한다. 2025-01-22부터 통화·알람 앱만 기본 허용이다. `[확인 필요: 3차 설계 결정]`
- 쓴다면: Play Console 신고, 사용자 허용 흐름, 허용하지 않으면 헤드업 알림과 반복 진동으로 대신한다.
- 완료 조건
  - [ ] 허용 안 된 기기에서도 알림이 놓치지 않게 울린다
  - [ ] Play 신고서와 시연 영상 준비

### LR3-06. 복약 문구와 잠금화면 (T-09)

- 홈·알림 안내: "복약 알림은 정해 둔 시간을 알려 드리는 기능이에요. 약의 효과나 복용 방법은 의사·약사에게 확인하세요."
- 잠금화면·알림 기본 문구: "약 드실 시간이에요" (약 이름 숨김). 사용자가 설정에서 약 이름 표시를 켤 수 있다.
- 음성 낭독: 이어폰이 연결됐을 때만 약 이름을 읽는 설정을 기본으로 둘지 정한다 `[확인 필요: 3차 설계 결정]`.
- 만들지 않는 것(의뢰서 MED-10): 효능, 주의사항, 상호작용, 용량 추천, 복용 순응도 점수로 처방 판단.
- 쓰지 않을 말: "복약 관리", "치료 효과", "약효".
- 의약품 제품명 검색(식약처 허가정보)은 제품명 후보만 보여 주고 효능·용법은 보여 주지 않는다.
- 완료 조건
  - [ ] 잠금화면 기본값에서 약 이름이 보이지 않는다
  - [ ] 처리방침 3절의 "민감정보가 드러날 수 있는 상황" 표에 반영
  - [ ] 문구 목록이 금지 표현 검사(검토서 §4.3)를 통과

### LR3-07. Play 신고와 계정 유형 (P-01, P-03)

- 2차 출시 전에 Play 지원팀에 묻는다: 개인 계정으로 Medication and Treatment Management를 신고할 수 있는지, 비법인 동아리가 D-U-N-S를 받을 수 있는지.
- 조직 계정이 필요하면 계정 이전 일정을 3차 일정에 넣는다(D-U-N-S 발급에 약 30일).
- 분류를 낮춰 신고하지 않는다.
- 완료 조건
  - [ ] Play 지원 회신 보관
  - [ ] `docs/play/health_apps_declaration.md` 3절 반영
