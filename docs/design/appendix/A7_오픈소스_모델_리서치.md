# See:Sun: 오픈소스·오픈웨이트 AI 모델과 라이브러리 조사 (기준일 2026-09-30)

대상은 Kotlin + Jetpack Compose Android 클라이언트와 Django 백엔드(서울 리전 1–2GB VM, CPU만 사용)입니다. 학생 동아리 프로젝트이고 상용 스토어 출시를 계획하고 있어 비용을 최소화하는 것을 전제로 했습니다.

**표기 규칙**
- [확인]: 이번 조사에서 PyPI나 Maven Central의 메타데이터를 직접 받아 확인한 사실입니다(버전, 라이선스 필드, 배포일).
- [S]: 웹 검색 결과 요약으로만 확인한 사실입니다.
- [미검증]: 기억이나 추정에 의존한 내용이라 출시 전에 반드시 원문을 확인해야 합니다.
- ⚠️: 라이선스나 정책상 함정입니다.

**조사 환경의 제약**
- Hugging Face API와 GitHub API는 이 세션에서 차단돼 모델 카드를 직접 읽지 못했습니다. HF 모델 라이선스는 모두 [S] 수준입니다.
- PyPI와 Maven Central(repo1)은 접근할 수 있었습니다. Google Maven(dl.google.com)은 접근하지 못했습니다.
- **모든 가중치 라이선스는 출시 전에 HF 모델 카드의 LICENSE 파일을 직접 확인해야 합니다.**

## 0. 한눈에 보는 결론

1. **"코드는 오픈소스"여도 "가중치나 학습 데이터는 비상업"인 경우가 매우 많습니다.** 한국어 음성 분야에서 특히 조심해야 할 것은 다음과 같습니다.
   - KSS 데이터셋(CC BY-NC-SA)으로 학습한 VITS, Glow-TTS, Tacotron, Piper 한국어 음성
   - Meta MMS(CC-BY-NC 4.0)
   - Coqui XTTS-v2(CPML 비상업, 회사가 폐업해 상용 라이선스를 살 방법도 없음)
   - F5-TTS 공식 가중치(Emilia 데이터, CC-BY-NC)
   - Fish-Speech/OpenAudio S1-mini(CC-BY-NC-SA)
   - openWakeWord 사전학습 모델(CC BY-NC-SA)
   - EXAONE(NC), Kanana-nano 2.1B와 Kanana-2(CC-BY-NC)
   - Qwen2.5-VL-3B(Qwen Research License, 비상업)
   - Picovoice 무료 플랜(현재 비상업 전용)
   - AI Hub(KsponSpeech 등)로 학습한 모델: 상업적으로 쓰려면 운영기관과 별도로 협의해야 합니다.
2. **상업적으로 안전한 핵심 조합(1차 추천)**
   - STT: **sherpa-onnx(Apache-2.0) + SenseVoiceSmall(FunASR Model License, 상업 허용·출처 표시)**, 또는 **Qwen3-ASR-0.6B(Apache-2.0)**. 온디바이스로 돌리고 Silero VAD(MIT)로 발화 단위를 잘라 넣습니다.
   - TTS: **Android 시스템 TTS**로 실시간 안내를 하고, 사전 생성 음성은 **Supertonic 3(OpenRAIL-M)**, **CosyVoice 3(Apache-2.0)**, **Chatterbox Multilingual(MIT)** 중에서 품질을 비교해 고릅니다.
   - OCR: **ML Kit 한국어(무료, 비오픈)가 기준선**입니다. 오픈소스 대안은 **PP-OCRv5 korean mobile(Apache-2.0, 12.8MiB)을 ONNX로 변환한 것**이고, 영양성분표는 규칙 기반 파서로 처리합니다.
   - 바코드: **zxing-cpp(Apache-2.0, `io.github.zxing-cpp:android` 3.1.1)**
   - NLU: **Kiwi(v0.24.0부터 Apache-2.0으로 바뀜, Android AAR 제공)**, 직접 만든 숫자·단위 문법, RapidFuzz와 자모 단위 유사도를 씁니다. LLM이 필요하면 **Qwen3/Qwen3.5 소형(Apache-2.0)** 또는 **Gemma 4 E2B(Apache-2.0)**, **Kanana-1.5-2.1B(Apache-2.0)** 중에서 고릅니다.
   - 음식명 검색: **pg_trgm과 자모 분해, 동의어 사전을 먼저 쓰고**, 부족하면 multilingual-e5-small(MIT) 임베딩을 미리 계산해 pgvector에 둡니다.
3. **2GB 서버에서는 STT, TTS, LLM, VLM 추론을 돌리지 않는 것이 원칙입니다.** Django, Postgres, 캐시만으로도 메모리가 빠듯합니다. 무거운 모델은 온디바이스로 돌리거나, 개발 PC나 Colab에서 미리 생성하는 오프라인 배치로 처리합니다.

**"시선 코치" 웨이크워드를 만들 수 있는지**
- 1순위는 sherpa-onnx open-vocabulary KWS입니다. 한국어 KWS 모델에 "시선 코치"를 토큰열로 등록하고 오탐률과 검출률을 PoC로 잽니다.
- 한국어 KWS 가중치의 데이터 출처(AI Hub 여부)가 불명확하면, Zeroth(CC BY 4.0)와 Common Voice ko(CC0)로 icefall KWS 레시피를 직접 학습하는 것이 가장 깨끗합니다. GPU 수 시간 규모로 예상합니다 [미검증].
- 시각장애인 사용자에게는 **볼륨키 두 번 누르기 같은 하드웨어 트리거와 TalkBack 제스처를 기본으로 두고, 웨이크워드는 옵션으로 두는 것**을 권장합니다. 상시 마이크를 켜 두면 배터리와 개인정보 부담이 생깁니다.

### 1-3. STT 추천
- **1차 추천: sherpa-onnx(AAR, Kotlin) + Silero VAD + SenseVoiceSmall int8, 온디바이스.** 발화가 끝나는 즉시(VAD end-point) 인식하므로 짧은 명령에서 체감 지연이 작을 것으로 예상합니다. 출처 표시(FunASR 라이선스 고지)를 반드시 넣어야 합니다.
- **비교 후보: Qwen3-ASR-0.6B int8(Apache-2.0, 핫워드 지원).** 음식명과 알레르기 어휘 정확도가 SenseVoice보다 높으면 교체합니다. 중급기의 메모리가 관건입니다.
- **오픈소스 폴백:** Vosk small-ko를 grammar 모드로 써서 "다음", "반복", "그만" 같은 고정 명령을 인식합니다. 또는 whisper.cpp base/small을 씁니다.
- **기준선:** Android `SpeechRecognizer`(온디바이스). 오픈 모델이 기준선보다 나쁘면 기준선을 1차로 씁니다.
- **서버 STT는 하지 않습니다.** 2GB VM에 올리면 Django와 메모리 경합이 생기기 때문입니다.

**영양성분표 파싱 전략(추천)**
1. OCR로 라인과 좌표를 얻습니다(ML Kit 또는 PP-OCRv5).
2. 행 클러스터링을 합니다. y좌표로 행을 묶고 x좌표로 열을 나눕니다.
3. **규칙 기반 키-값 추출**을 합니다.
   - 키 사전: 열량, 나트륨, 탄수화물, 당류, 지방, 트랜스지방, 포화지방, 콜레스테롤, 단백질 등. 식약처 표시기준에 나오는 항목 순서가 고정돼 있어 사전을 만들기 쉽습니다.
   - 정규식: `(\d+(\.\d+)?)\s*(kcal|mg|g)` 와 `(\d+)\s*%`
   - 오탈자 보정: RapidFuzz와 자모 유사도를 씁니다("나트룸"→"나트륨").
   - "총 내용량 / 100g당 / 1회 제공량" 기준을 인식합니다.
4. 신뢰도가 낮으면 사용자에게 "다시 비춰 주세요"라고 음성으로 안내합니다. 카메라 가이드도 음성으로 합니다("조금 더 왼쪽").
5. VLM은 **개발 단계의 라벨링 보조와 테스트 데이터 생성용**으로만 씁니다.

**OCR 추천**
- 1차: **ML Kit Korean**(무료, 가장 적은 공수)
- 오픈 폴백: **PP-OCRv5 korean mobile을 ONNX로 변환해 onnxruntime-android로 실행**(Apache-2.0)
- PoC: 영양성분표 50장으로 필드 단위 정확도를 비교합니다.
