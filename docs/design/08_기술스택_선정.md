원칙
1. **음성·사진은 기기 안에서 처리**하고, 서버에는 확인을 거친 구조화 데이터만 보냅니다.
2. **Android 공식 API·Jetpack을 우선**합니다. 핵심 기능(알람·접근성·음성)을 개인 유지보수 라이브러리에 걸지 않습니다.
3. **1차 백엔드를 보강해 재사용**합니다.
4. 무료 한도로 시작하고 과금 항목은 사용량 경보를 둡니다.

### 4.1 플랫폼·프레임워크 (D-01 확정)

| 기준 | 가중치 | Kotlin + Compose | React Native + Expo | Capacitor(1차 웹) | Flutter |

| **합계(100)** | | **73** | **71** | 61 | 58 |

**최종 선택: Kotlin + Jetpack Compose (Android 네이티브).**
- 2·3차 의뢰서의 플랫폼은 Android뿐이고, 핵심 요구(정확한 알람·전체화면 알림·SMS 자동입력·진동 파형·live region)가 모두 Android 공식 API에 직결됩니다.
- RN을 골라도 이 기능들은 Kotlin으로 직접 짜야 해서, RN의 팀 역량 이점이 줄어듭니다.
- **팀 역량 보완:** Compose는 React와 같은 선언형·상태 기반 모델이라 개념 전환이 작습니다. T1 PoC 1주를 Kotlin 적응 기간으로 겸하고, 공통 모듈(디자인 시스템·a11y·voice)을 먼저 만들어 나머지 화면은 패턴을 따르게 합니다.
- **전환 조건:** iOS 동시 출시가 확정되면 RN(또는 Kotlin Multiplatform)을 재검토합니다.
