## 0. 핵심 기준(요약)

1. **화면은 위 "보는 영역", 아래 "누르는 영역"으로 나눈다.** 헤더(64dp) → 본문(위부터 채움) → 남는 공간 → 하단 행동 영역. 주요 버튼은 하단 행동 영역 맨 위, 화면 높이 60% 아래에 중심이 온다. [1][2][3]
2. **기본 글꼴에서는 스크롤이 없다(3차).** 긴 글은 쪽으로 나누고(§6-1), 낮은 화면은 단계(§6)로 줄인다. **글꼴을 키우면(1.3·2.0) 하단 행동은 고정하지 않고 본문 끝에 붙어 함께 스크롤된다.** 고정 막대가 확대된 글자를 가리지 않게(WCAG 1.4.10 리플로). [4][5]
3. **좌우 여백 20dp(폭 <600dp, Figma 필수) / 24dp(≥600dp), 본문 열 최대 600dp 가운데 정렬. 보통 폰은 헤더 위 36dp·묶음 사이 24dp(Figma 필수), 작은 폰은 4·8dp.** 넓은 화면에서 버튼·글줄을 화면 끝까지 늘리지 않는다. [6][7][8]
4. **버튼 높이 최소 74dp(Figma 316×74, 낮은 화면 64dp), 회색 보조 버튼 56dp, 터치 영역 48dp 이상, 버튼 사이 12dp(최소 8dp).** [9][10][11]
5. **버튼 글자는 한 줄이 원칙.** 두 버튼을 나란히 둘 때 한 줄에 안 들어가면 자동으로 세로로 쌓는다. 보조 버튼 쌍·메뉴 타일만 어절 단위 2줄까지 허용. [12][13][14]
6. **한국어는 어절 단위로만 줄바꿈한다**(`LineBreak.Heading`/`WordBreak.Phrase`, API 33 미만은 단어 잇기 문자). 어절 중간 끊김("로그/아웃")은 결함. [15][16][17]
7. **가장 작은 글자 18sp**(KRDS 본문 최소 16px보다 크게, 저시력 사용자). 예외는 접기에서 펼친 약관·고지 전문 15sp 하나(4차, 소유자 허락 msg 800, §6-1). 버튼 28sp(나란히 22sp), 본문 20sp, 제목 40sp(길면 32sp), 음성 질문 30sp. [18]
8. **하단 행동 영역의 주요 버튼은 하나**, 세로로 쌓을 때는 중요한 것이 위. 노랑은 Figma처럼 선택지·메뉴 타일의 기본색이기도 하므로, 보조 동작은 회색 칩(#DCDCDC)으로 낮춘다. [12][19]

## 1. 창 폭 구분과 열 폭

| 항목 | 값 | 근거 |
|---|---|---|
| 폭 구분 | compact <600dp · medium 600–839dp · expanded ≥840dp (`WidthClass.of`) | M3 breakpoints [6] (Android 공식 `WindowSizeClass` 경계와 같음 [20]) |
| 좌우 여백 | compact 20dp · medium 이상 24dp | 의뢰인 Figma layout guide 「모든 페이지 좌우 패딩 20」(2026-10-14 변경, 전에는 M3 16) · KRDS 16/24px [21] |
| 본문 열 최대 폭 | 600dp(헤더·본문·하단 행동이 같은 열), 가운데 정렬 | 버튼·입력칸 전체 폭 금지 [7], 줄 길이 40–60자 [6][8], WCAG 1.4.8 CJK 40자 [22] → 20sp 한글 한 줄 약 30자 **[자체 결정: 600dp]** |
| 2단(목록-상세) | 쓰지 않음(현재 화면이 한 흐름 단계형) | 정규 레이아웃 [23]는 참고만, 넓은 화면은 가운데 열로 충분 — §11 한계 |

Compose 구현은 새 의존성 없이 `BoxWithConstraints` 폭으로 구분한다(`androidx.window` `WindowSizeClass`와 경계값 동일). 공식 API(`currentWindowAdaptiveInfo`)는 adaptive 1.3.0에서 V2로 바뀌는 중이라 [20] 도입을 미뤘다.

## 2. 화면 영역 배분

```
┌──────────────────────────┐  ← 상태바(시스템, safeDrawing)
│ ◀  제목(40sp)       🔊   │  헤더 72dp(낮은 화면 60) + 진행 막대    ┐
├──────────────────────────┤                                        │ 보는 영역(viewing area [1])
│ 본문: 안내 1~2줄·입력·목록  │  위에서부터 채움                        │
│                          │                                        ┘
│      (남는 공간)          │  본문과 행동 사이에만 생김
├──────────────────────────┤                                        ┐
│ [ 주요 버튼 ]  (노랑)      │  하단 행동 영역(BottomActions)          │ 누르는 영역(interaction area [1])
│ [ 보조 ] [ 보조 ]          │  아래 여백 16dp                         ┘
└──────────────────────────┘  ← 내비게이션 바(시스템)
```

| 규칙 | 값 | 근거 |
|---|---|---|
| 헤더 | 한 줄 72dp(낮은 화면 60): 회색 삼각형 뒤로(누르는 곳 56dp)·제목 40sp(한 줄이면 가운데, 길면 32sp 왼쪽)·요약 듣기. 온보딩 진행은 「n/7」 글자 대신 아래 노랑 진행 막대. 음성 입력 화면은 제목 대신 본문의 큰 질문 | 의뢰인 Figma 뒤로가기 325:1564·Title M 40 · M3 toolbar 64dp [24] |
| 본문 | 위에서부터. 화면 안내는 핵심 1~2줄, 자세한 말은 TalkBack 설명·[화면 요약 듣기] | 04 §5, 소유자 피드백 2026-10-13 |
| 하단 행동 영역 | 화면의 [다음]·[저장]·[확인]·메뉴 타일. 주요 버튼 중심이 화면 높이 **60% 아래** | One UI viewing/interaction area [1], Android "reachable area" [2], 토스 BottomCTA(하단 고정) [3] **[자체 결정: 60%]** |
| 빈 공간 위치 | 본문과 하단 행동 사이(`BottomActions`의 weight 빈 칸). 주요 버튼 아래로 빈 공간을 두지 않는다 | 위와 같음 |
| 고정 여부 | 본문이 화면에 들어가면 화면 아래에 붙고, 넘치면 본문 끝에 이어 붙어 함께 스크롤 | WCAG 1.4.10 [4], Apple "stacked layout"·잘림 최소화 [5]. 토스는 `fixedAboveKeyboard`로 고정 [3] — 우리는 큰 글꼴 사용자가 많아 고정을 택하지 않음 **[자체 결정]** |
| 메뉴 화면 | 메인·운동·마이페이지·설정의 메뉴 타일 묶음도 하단 행동 영역에 둔다(요약 카드가 위) | "Keep essential interactions, such as primary navigation, in a reachable area" [2] |
| 화면 아래 여백 | max(16dp, 시스템 제스처 영역 − 내비게이션 바). 제스처 힌트를 숨긴 폰은 바가 0dp라 맨 아래 25dp가 홈 제스처 영역 | 실기기 실측(Galaxy A55, One UI 8.5: 상태바 34dp, 내비 바 0dp, 아래 제스처 영역 25dp) · Compose `WindowInsets.mandatorySystemGestures` |

**반대 근거와 판단**: Hoober(2017)는 사람들이 화면 **가운데**를 보고 누르기를 선호하고, 2013년 "엄지 영역" 도식은 저자가 정정했다고 밝혔다 [25]. 그래서 "아래 = 무조건 쉬움"이 아니라 ① 주요 버튼을 가운데~아래(60% 아래)에, ② 모서리가 아닌 **전체 폭 큰 버튼**(모서리 정확도 12mm 필요 [25])으로 두는 것으로 정했다. TalkBack 사용자는 위치보다 순서로 찾으므로 낭독 순서(제목 → 본문 → 주요 버튼)도 함께 맞췄다.

**레이블 길이 예산(360dp 폰, 기본 글꼴, 한글 1자 ≈ 글자 크기)**: 전체 폭 버튼 24sp → 약 12자, 반 폭 버튼 20sp → 약 6자. 넘으면 자동으로 세로 배치되므로 화면은 깨지지 않지만 높이를 더 쓴다. 새 문구는 이 예산 안에서 짓는다.

**비활성 사유**: 버튼 안이 아니라 버튼 바로 위 한 줄(노랑 18sp, `DisabledReason`). 버튼 레이블이 늘 한 줄로 남고, TalkBack은 사유 → "다음, 버튼, 사용 중지됨" 순으로 읽는다.

## 4. 글자·한국어 줄바꿈

| 스타일 | 크기/줄높이 | 줄바꿈 |
|---|---|---|
| 제목 `screenTitle` / `screenTitleSmall` | 40/48 · 32/40sp 굵게(Figma Title M·S) | `LineBreak.Heading` |
| 음성 질문 `prompt` | 30/38sp 아주 굵게(Figma 32, 360dp 두 줄 맞춤) | Heading |
| 버튼 `button` / `buttonCompact` | 28/34 · 22/28sp 굵게(Figma Button_large 32에서 한 단계 낮춤) | Heading |
| 목록 `listItem` / 강조 | 26/32 · 32/40sp 굵게 | Heading |
| 메인 타일 `tile` | 34/40sp 굵게 | Heading |
| 결과 `result` | 30/36sp 굵게 | Heading |
| 본문 `body` | 20/28sp | Paragraph + `WordBreak.Phrase` |
| 캡션 `caption`(가장 작은 글자) | 18/24sp | Paragraph + Phrase |

- 크기 근거: KRDS 본문 최소 16px·기본 17px·줄간격 150% [18], 저시력 사용자 대상이라 한 단계 크게 **[자체 결정: 최소 18sp]**. 15sp·14sp 글자는 모두 없앴다.
- **왜 명시해야 하나**: Compose 글자는 줄바꿈을 지정하지 않으면 `LineBreak.Simple`(WordBreak.Default)이라 targetSdk 35여도 한국어가 글자 단위로 끊긴다(TextView만 자동 PHRASE) [15]. `LineBreak.Heading` = Balanced + Loose + **WordBreak.Phrase** [15], Phrase는 "titles and UI labels"에 맞는 어절 단위 [16]. Android 15 문서: 한국어 phrase 줄바꿈은 API 33부터, API 35의 AUTO는 한국어면 길이와 상관없이 PHRASE [17].
- **기기마다 다르다(실측)**: 같은 앱(수정 전)에서 Galaxy A55(One UI 8.5, Android 16)는 한국어를 띄어쓰기에서 끊었고(어절 중간 끊김 0/49화면), AOSP 에뮬레이터(Android 16)는 같은 화면들을 글자 단위로 끊었다(412×915에서 51/86화면). 삼성 기본 동작에 기대지 않고 앱이 직접 Phrase를 지정해야 모든 기기에서 같다.
- **API 26–32**: Compose는 API 33 이상에서만 `LineBreakConfig`를 넘기므로 [15] `keepAllCompat()`가 어절 안 글자 사이에 단어 잇기 문자(U+2060)를 넣는다(CSS `word-break: keep-all`과 같은 효과 [26]). 버튼·타일·제목·확인 줄에 적용. 보이지 않고 읽히지 않는다.
- **허용되는 끊김**: 한 어절이 한 줄보다 길 때만(어쩔 수 없는 끊김, 판정은 기록만). 같은 줄에 띄어쓰기가 있었는데 어절 안에서 끊기면 위반.
- **반대 근거**: 토스는 큰 글자 모드 메뉴에서 공간을 줄이려 글자 단위 개행을 택했다 [27]. 우리는 낭독과 함께 읽는 저시력 사용자에게 어절 보존이 더 중요하다고 보고 Phrase를 유지하되, 글꼴 200%에서 한 어절이 넘치면 플랫폼이 끊도록 둔다(§6).

## 5. 간격 토큰(4dp 격자)

`SeeSunSpace`: XS 4 · S 8 · M 12 · L 16 · XL 24 · XXL 32dp. 화면 여백 20/24(2026-10-14, 전에는 16/24), 묶음 사이 24(보통 폰, `SectionGap`)·8(작은 폰), 같은 묶음 안 12(`SeeSunDimens.Gap`), 버튼 안 세로 8, 행동 영역 아래 16. 여백·높이는 dp, 글자만 sp(비선형 글꼴 확대에서 "4sp + 20sp ≠ 24sp" [11]). 근거: 8dp 기본 격자·작은 요소 4dp [28].

### 6-2. 남는 높이를 받는 자리(3차)

추정 높이 상수(예: 메인 「로고·[설정]·간격 = 256dp」) 대신, 본문 열에서 다른 요소를 먼저 재고 남는 높이를 한 자리에 준다(`Modifier.weight`, 하단 행동은 `BottomActions(pushDown = false)`).
- 운동 재생: 그림·대본 자리(그림 최대 300dp, 그림 띠 64/52/48dp) → 지금 문장 → 상태 줄([대본 보기]) → [이전 구간][재생][다음 구간] · [다시 듣기][속도] · [마치기][즐겨찾기]. 재생 버튼은 가운데 넓게(1 : 1.6 : 1), 글자가 두 줄 안에 안 들어가면 예전처럼 세로.
- 메인 타일: 남는 높이의 반(96~210dp, 보통 폰은 Figma 210dp 그대로).
- 알레르기 휠: 남는 높이(최대 292/360dp).
- 글꼴을 키우면 이 자리는 예전처럼 고정·추정 높이로 두고 본문이 스크롤된다(남는 높이가 0이 되어 그림이 사라지지 않게).

## 11. 남은 한계

- 넓은 화면(≥840dp)도 한 열 600dp다. 빈 좌우 공간을 쓰는 2단(목록-상세·보조 패널)은 화면별 설계가 필요해 이번 범위에서 뺐다.
- 한 어절이 한 줄보다 긴 경우(글꼴 200%의 "킬로칼로리(추정값)" 등)는 플랫폼이 어절 안에서 끊는다(기록만).
- API 26–32의 단어 잇기 문자 대체는 단위 시험으로만 확인했다(시험 기기는 API 36).
- 쪽 나누기는 읽는 흐름을 끊는다. 화면 낭독 사용자는 쪽마다 [다음 쪽]을 눌러야 한다(대신 스크롤 위치를 잃지 않고 「n/m쪽」으로 위치를 안다). 의뢰인 확인 필요(FIGMA_ALIGN_REPORT §10).
- 아주 작은 폰 단계의 설명 줄 접기는 정보를 TalkBack에만 남긴다(저시력 사용자는 화면에서 못 본다). 값이 정보인 화면(건강 정보 수정의 지금 값)은 접지 않았다.
