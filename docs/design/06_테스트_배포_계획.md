## 3. 사용성 테스트 설계 (차수별 1회 이상)

- **참여자:** 전맹·저시력 각 3~5명(의뢰인 모집), TalkBack 숙련도 다양하게. 보조자 동반 가능.
- **방식:** 대면 관찰 + 사고 발화, 화면 가림(저시력자) 조건, 과업 성공률·소요 시간·오류·도움 요청 횟수, SUS 설문(음성 진행).
- **2차 과업(검수 기준 매핑)**
  1. 앱 설치 후 온보딩 완료(동의·SMS 인증 포함) — 검수②
  2. 음성으로 점심 식사 2가지 기록 — 검수②③
  3. 과자 포장 바코드 촬영 기록 — 검수③
  4. 알레르기 경고와 당류 경고를 진동·음성만으로 구분 — 검수⑤
  5. 비행기 모드에서 식사 기록 → 복구 후 전송 확인 — 검수④
  6. 단백질 음식 추천 받기, 선호 식단 저장 — 검수②
  7. 오늘의 식단 점수 듣기, 운동하러 가기 — 검수①
  8. 메인에서 운동 방식 → 스쿼트 재생 → 마이페이지 주간 운동 확인 — 검수②
- **3차 과업:** 음성으로 약 등록, 약봉투 촬영 등록, 알림 수신 후 복용 기록, 재부팅 후 알림 확인, 주간 복약률 듣기.
- **기기 매트릭스:** Android 10/12/14/15/16, 삼성(One UI)·픽셀 최소 각 1대, TalkBack 최신/구버전, 저사양 1대(배터리 최적화·Doze 확인).

## 5. Google Play 출시 절차

1. **개발자 계정:** enVision 조직 계정(D-08, D-U-N-S 필요). 개인 계정이면 **비공개 테스트 12명·14일 연속** 필수.
2. 앱 등록: 패키지명, Play App Signing, targetSdk 36 AAB.
3. 정책 신고: Health apps 신고서, Data safety, 정확한 알람·전체화면 인텐트·포그라운드 서비스 신고, 대상 연령(14+ 또는 18+), 콘텐츠 등급.
4. 스토어 등록정보: 치료·진단 표현 없는 설명, 접근성 안내, 개인정보 처리방침 URL, **계정 삭제 웹 URL**.
5. 트랙: 내부 → 비공개 → (프로덕션) 단계적 출시.
6. 출시 후: 크래시·ANR 모니터링, 리뷰 대응, 접근성 문의 채널 운영.

## 7. 레포·협업 정리 (D-10)

1. `dev` → `main` 병합, `main`을 기본·배포 브랜치로.
2. 반영 완료 브랜치 3개 삭제, 미병합 2개는 태그 보관 후 삭제.
3. 열린 이슈 18건을 코드 기준(부록 A1 §8)으로 닫거나 재분류, 2·3차 요구 ID로 이슈 재생성.
4. 모노레포: `android/`, `backend/`, `docs/`(공개 가능한 요구·설계), 보안·법적 상세는 비공개 저장소(D-11).
5. Git Flow·커밋 규칙은 Notion 팀 컨벤션 유지, PR 2인 승인.
