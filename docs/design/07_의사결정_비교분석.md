# 07. 의사결정 비교 분석 (D-01 · D-03 · D-04/05 · D-07 · D-08 · D-11)

> 방법: 결정마다 **선택지 → 평가 기준(가중치) → 1~5점 채점 → 가중 합계(100점 환산) → 권장안과 전환 조건**.
> 법적 필수 요건을 충족하지 못하는 선택지는 점수와 무관하게 **탈락(게이트)** 처리합니다.
> 점수는 현재까지의 분석(부록 A1~A3)과 팀 구성(1차 커밋 기준: React/TypeScript 프론트 3명, Django 백엔드 3명)에 근거한 판단입니다. 라이브러리 지원 여부처럼 검증이 필요한 부분은 **PoC 항목**으로 따로 적었습니다.

### 권장안
- **권장: A.** 2차 의뢰서(§7 "Android 기본 음성 인식 + 후처리, 음성 명령은 키워드 매칭")와도 일치합니다.
- 유저테스트에서 필드별 인식 성공률이 90%에 못 미치면 D(서버 LLM 보조, 명시적 동의 후)를 추가 검토합니다.
- 1차 서버의 `stt` 앱은 운영에서 비활성화하고, 남긴다면 인증·요청 제한·로그 제거를 적용합니다.

### ①을 채택할 때 필수 조치
1. **시크릿:** `SECRET_KEY`·DB 비밀번호 등 모든 설정을 환경변수로(`.env`는 git 제외 유지), 운영 키는 새로 발급해 GitHub Secrets / AWS Secrets Manager에만 보관. GitHub **secret scanning + push protection** 켜기, CI에 시크릿 검사(gitleaks 등) 추가.
2. **내부 문서 제거(시점: 2·3차 개발 완료 후, 2026-09-30 결정):** `prototype` 브랜치(회의록·의뢰서·원고·.ai 원본)를 2·3차 완료 시점에 삭제합니다. 그때까지는 이 브랜치에 새 내부 문서를 추가하지 않고, 앞으로 내부 문서는 Drive `테크팀/`에만 둡니다. 브랜치를 지워도 커밋이 해시로 한동안 접근 가능하고 포크에 남을 수 있으므로, 필요하면 GitHub 지원팀에 캐시 삭제를 요청합니다.
3. **콘텐츠 자산 분리:** 픽토그램·운동 음성·가이드 대본은 레포에서 빼고 Cloudflare R2(비공개 원본 + CDN 공개 배포본)로 이동. 레포에는 샘플 몇 개와 불러오는 스크립트만. 공개를 유지할 자산은 저작자(디자인팀·가이드팀) 동의를 받고 코드와 **별도 라이선스**(예: CC BY-NC)로 명시.
4. **라이선스 정리:** 코드 라이선스를 하나로(Apache-2.0 유지 여부 결정, package.json MIT 표기 정리). 외주 계약서의 저작권 양도 조항과 충돌하지 않는지 확인.
5. **보안 결함은 서버 공개 전에 수정**(01 문서 P0).
6. **문서 보관:** `docs/design/` 01~07은 공개 레포, 세부 근거 부록(A1~A3)과 계정·비밀 정보는 Drive `테크팀/` 비공개 폴더(또는 비공개 저장소).
