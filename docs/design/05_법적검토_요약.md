## 3. 통합 체크리스트

### (A) 데모 APK 유저테스트 전 필수
- [ ] 연세대 IRB에 심의 대상 여부를 문의하고, 필요하면 승인을 받는다(장애인, 건강정보).
- [ ] 접근 가능한 형식(음성·스크린리더 텍스트·대면 낭독 + 증인)의 테스트 참여 동의서를 준비하고 서명 또는 녹음 기록을 남긴다.
- [ ] 테스트용 개인정보 수집·이용 동의서(항목, 목적, 보유기간, 파기일, 외부 AI 전송 고지, 철회권)를 만든다.
- [ ] 가상 프로필을 쓰도록 안내하고, 실제 질환·약 입력은 선택으로 둔다. 테스트 서버를 분리하고 종료 후 파기한다.
- [ ] 음성 원본의 서버 저장을 끄거나 저장 기간을 명시한다. Cloud STT data logging을 끈다. **Gemini는 유료 티어 키만 쓴다.**
- [ ] 테스터를 만 18세 이상으로 한정한다(Gemini 약관, 미성년자 동의 문제 회피).
- [ ] 앱 안에 "의료기기 아님 / 참고 정보" 면책과 알레르기 참고정보 고지를 넣는다.
- [ ] "당뇨 위험도" 명칭과 등급 문구를 성분 기준 표현으로 바꾼다(최소한 테스트 빌드 문구부터).
- [ ] 운동 안전: 공간 안내와 즉시 중단 명령을 넣고, 조깅을 제외하거나 보조자를 배치한다. PAR-Q+ 사전 확인을 한다.
- [ ] 빌드 보안: 하드코딩 키 제거, 디버그 로그의 개인정보 제거, 테스트 후 삭제 안내.
- [ ] 외주사가 테스트 데이터에 접근한다면 위탁·비밀유지 약정을 맺는다.
- [ ] 사례비 지급 방식과 세무 처리를 확인한다.
- [ ] (개인 개발자 계정이라면) 테스트 참여자를 Play 비공개 테스트 12명/14일 요건과 연계할지 결정한다.

### (B) Play 스토어 출시 전 필수
- [ ] 이용약관과 **개인정보 처리방침**(작성지침 2025.4. 반영, 웹 URL + 앱 내 음성 낭독)을 준비한다.
- [ ] 동의 구조를 분리한다: 약관(필수) / 개인정보 고지 / **민감정보 별도 동의(선택, 거부해도 일반 모드 이용 가능)** / 국외이전 고지(또는 동의) / 광고성 정보(선택, 없으면 생략).
- [ ] 만 14세 미만 가입을 차단한다(또는 법정대리인 동의·확인 흐름을 만든다). Gemini를 쓰는 동안은 **18세 이상 연령 게이트**를 둔다.
- [ ] 동의 기록(버전·시각·방법)을 저장하고, 동의 철회와 권리 행사 경로(음성·전화 포함)를 둔다.
- [ ] 위탁과 국외이전 목록을 확정하고(Firebase, GCP, Gemini, AWS, NHN, Naver, Sentry 등) 처리방침에 반영한다. 가능하면 서울 리전을 쓴다.
- [ ] 안전조치: 전송 TLS, PIN 해시, 민감정보 컬럼·로컬 DB 암호화(권장이지만 사실상 필수로 취급), 접근권한과 접속기록 관리, 72시간 유출가능성 통지 절차.
- [ ] 계정 삭제: 앱 안(음성 포함) + **웹 삭제 요청 페이지**. DB·백업(R2), Firebase, 로그까지 파기한다.
- [ ] Data safety 양식을 작성한다(건강, 오디오, 사진, 전화번호, 크래시 로그, SDK 수집분). 처리방침과 일치해야 한다.
- [ ] Health apps 신고서를 작성한다. 스토어 설명에 치료·진단 주장을 넣지 않고 면책을 명시한다.
- [ ] targetSdk 36(Android 16)으로 맞춘다.
- [ ] SMS 권한을 쓰지 않는다(SMS Retriever / Firebase auto-retrieval).
- [ ] SCHEDULE_EXACT_ALARM(사용자 허용 흐름과 대체 알람)을 쓰고, USE_EXACT_ALARM은 쓰지 않는다. 재부팅·시간 변경 시 알람을 다시 등록한다.
- [ ] USE_FULL_SCREEN_INTENT: Play 신고, 사용자 허용 흐름, 대체 알림을 만든다.
- [ ] 포그라운드 서비스 타입(mediaPlayback / microphone)을 선언하고 Play에 신고한다.
- [ ] 개발자 계정: 책임자 개인 계정(D-08)이므로 12명·14일 비공개 테스트를 완료한다.
- [ ] Play 대상 연령을 18세 이상(또는 14세 이상)으로 설정해 Families 정책 비대상을 확인한다.
- [ ] 공공데이터 이용 조건을 확인하고 "데이터 출처" 화면을 만든다. 공공누리 제2유형(국가표준식품성분표)은 상업적 이용 금지이므로 쓰지 않는다. 코리안넷을 쓴다면 계약한다.
- [ ] 의약품 허가정보 API 운영 계정 승인을 받는다. 효능·주의사항을 표시하지 않는다.
- [ ] 알레르기 목록을 데이터로 관리하는 구조(참깨 등 추가 대비)와 오류 신고 기능을 만든다.
- [ ] 오픈소스 라이선스 화면, 외주 IP 양도 계약, 서명 키와 콘솔 계정 소유권을 확보한다.
- [ ] 접근성: KS X 3253 최신판 체크리스트로 자체 점검하고, 접근성 안내와 문의 채널(전화·문자·이메일)을 둔다.
- [ ] 알람에서 약 이름을 읽는 기능은 기본 끔(또는 이어폰 연결 시만)으로 두고, 잠금화면에서는 약 이름을 숨긴다.

### (C) 권장
- [ ] 식약처에 의료기기 해당 여부를 질의한다(당류 지표, 질환별 추천).
- [ ] 변호사에게 약관, 처리방침, 면책 조항, 외주 계약을 검토받는다.
- [ ] PIPC 사전 상담(키·체중 분류, 음성 동의 방식)을 받는다.
- [ ] 디지털의료·건강지원기기 자율 신고나 성능인증을 검토한다(출시 후).
- [ ] 정보접근성 품질인증(모바일앱)을 검토한다.
- [ ] 온디바이스 STT/TTS로 전환해 국외이전과 음성 처리 리스크를 줄인다. Gemini를 대체하면 미성년자 지원도 가능해진다.
- [ ] 미성년자를 허용한다면 한국인 영양소 섭취기준(연령별)을 적용하고 감량 목표를 제한한다.
- [ ] 운동 콘텐츠 전문가 감수와 배상책임보험을 검토한다.
- [ ] 장기 미이용자 데이터 파기 정책(1~2년)을 둔다.
- [ ] 가명처리 기반 서비스 개선 통계 체계를 만든다(처음에는 집계만).
- [ ] Health Connect 연동은 추후 선택 기능으로 둔다.

## 4. 동의·고지 화면(04 문서 LGL-01~07에 반영) (순서와 음성 안내 고려사항)

**공통 음성 원칙**
- 각 화면은 "화면 이름 → 한 문장 요약 → 중요 항목(민감정보·국외이전·보유기간·거부 시 불이익) → '자세히 듣기' 선택 → 동의/동의 안 함" 순서로 안내합니다.
- 자동으로 넘어가지 않습니다(타임아웃 없음). "다시 듣기", "천천히 듣기", "건너뛰기(선택 항목만)" 음성 명령을 지원합니다.
- 음성 동의는 **재확인 질문**을 거치고, 터치 대안(두 번 탭)을 함께 제공합니다. 동의 결과를 음성으로 알려 줍니다("건강정보 처리에 동의하셨습니다. 설정에서 언제든 철회할 수 있습니다").
- TalkBack이 켜져 있으면 자체 TTS를 중단하거나 TalkBack 흐름으로 넘깁니다. 모든 버튼에 역할과 필수/선택 여부를 레이블로 붙입니다.
- 체크 상태를 미리 켜 두지 않습니다. "전체 동의"를 두더라도 음성으로 포함 항목을 먼저 읽어 줍니다.
