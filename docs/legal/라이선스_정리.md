## 2. 제안: 코드는 Apache-2.0 하나로, 콘텐츠는 따로

### 2.1 코드

- 저장소의 **코드 전체는 Apache-2.0**으로 통일합니다.
  - 이유: 루트가 이미 Apache-2.0이고, 공개 저장소에서 Apache-2.0으로 공개한 코드는 이미 받은 사람에게 철회할 수 없습니다(검토서 §9.1). MIT로 바꾸는 것보다 Apache-2.0으로 맞추는 쪽이 변경이 작고, 특허 조항이 있어 더 보호적입니다.
- `frontend/package.json`을 고칩니다(개발자가 별도 커밋으로).
  ```json
  "license": "Apache-2.0",
  "private": true
  ```
  `private: true`는 npm에 실수로 올리는 것을 막습니다. 1차 프론트엔드에 이미 MIT로 기여한 부분은 MIT로도 계속 쓸 수 있으나, MIT와 Apache-2.0은 서로 함께 쓸 수 있어 충돌하지 않습니다.
- 루트에 `NOTICE` 파일을 둡니다(Apache-2.0 제4조 (d)). 초안:
  ```
  시선(See:Sun)
  Copyright 2026 enVision(연세대학교 학생 동아리) 및 기여자
  [확인 필요: 저작권자 표기 — 양도 완료 전에는 각 작성자, 완료 후 enVision(대표 ○○○)]

  이 저장소의 코드는 Apache License 2.0을 따릅니다.
  운동 대본, 운동 그림(픽토그램), 안내 음성 등 콘텐츠는 이 라이선스에 포함되지 않습니다. CONTENT_NOTICE.md를 보십시오.
  ```
- `README.md` 끝에 다음 절을 붙입니다.
  ```markdown
  ## 라이선스
  - 코드: Apache License 2.0 (`LICENSE`, `NOTICE`)
  - 콘텐츠(운동 대본, 픽토그램, 음성): 코드 라이선스에 포함되지 않습니다. 다시 쓰거나 배포할 수 없습니다. `CONTENT_NOTICE.md` 참고
  - 앱에 들어간 오픈소스 목록: 앱의 설정 > 오픈소스 라이선스
  ```
- 개발자에게서 enVision으로 저작권을 양도한 뒤에도, 이미 Apache-2.0으로 공개한 버전의 이용허락은 그대로 남습니다. 라이선스를 바꾸면 **그 뒤의 버전에만** 적용됩니다. 합의서에 이 점을 적습니다(K-03).

### 2.2 콘텐츠

- 콘텐츠는 **이용허락하지 않습니다.** 저장소 루트의 `CONTENT_NOTICE.md`로 알립니다(이번 작업에서 추가).
- 저작자별 이용허락서·양도서를 받은 뒤(L-05) 권리자를 `CONTENT_NOTICE.md`에 적습니다.
- 나중에 공개 라이선스(예: CC BY-NC-ND)로 풀지 여부는 권리 정리가 끝난 뒤 의뢰인이 정합니다.
- 장기적으로는 콘텐츠 원본을 공개 저장소에서 빼고, 비공개 저장소나 R2 비공개 버킷에서 빌드 때 가져오는 방식을 권장합니다. 공개 기간이 길수록 복제 위험이 커집니다(L-07).

## 4. L-06. 1차 운동 음성(mp3 234개) 생성 경위 확인 절차

**왜**: gTTS는 Google 번역의 비공식 경로를 쓰는 라이브러리라, 만든 음성의 이용 조건이 분명하지 않습니다. Google Cloud Text-to-Speech로 만든 음성은 Google Cloud 약관에 따라 이용할 수 있습니다. 사람이 녹음했다면 녹음한 사람(실연자)의 이용허락도 필요합니다.

**지금 알고 있는 단서**

| 단서 | 내용 |
|---|---|
| 1차 커밋 `05747ed`(2026-01-20) "각 운동별 픽토그램 및 오디오 생성" | 이 시점의 `update_media.py`는 `from gtts import gTTS`로 운동별 mp3를 만듦 |
| 커밋 `b93d513`(2026-01-26) "Update media generation scripts for Google TTS" | `generate_nav_audio.py`, `populate_name_en.py`만 바뀜. `update_media.py`(운동 음성)는 이 커밋에서 바뀌지 않음 |
| 커밋 `6fc7dce`(2026-01-26, `fix/tts_button_dev`) "Update generated audio files and fixtures" | 지금 복구 대상 mp3가 들어간 커밋 |
| 설계 문서 01 | "관리 명령: update_media(gTTS), generate_nav_audio(Gemini+Cloud TTS)" |
| 현재 코드 | `backend/apps/exercises/google_tts.py`(Cloud TTS, `ko-KR-Neural2-A`)가 있음. `update_media.py`는 gTTS가 없으면 실행을 막음 |

→ **운동 음성은 gTTS로 만들었을 가능성이 높습니다.** 아래 절차로 확인합니다.

**확인 절차**

1. 코드 이력: `6fc7dce` 시점의 `update_media.py`가 무엇으로 음성을 만들었는지 봅니다.
   ```bash
   git show 6fc7dce:backend/apps/exercises/management/commands/update_media.py | grep -n -i "gtts\|texttospeech\|google_tts"
   ```
2. 파일 속성: 복구한 mp3 몇 개의 표본(채널, 샘플링, 비트레이트, 인코더 태그)을 봅니다.
   ```bash
   ffprobe -hide_banner backend/media/exercises/audio/<운동>/<파일>.mp3
   ```
   - 같은 문장을 gTTS와 Cloud TTS(`ko-KR-Neural2-A`)로 새로 만들어 속성과 목소리를 비교합니다.
3. 결제 기록: 1차 Google Cloud 프로젝트의 Text-to-Speech 사용량·청구 기록(2026-01)을 계정 소유자가 확인합니다. 사용 기록이 없으면 Cloud TTS가 아닙니다. `[확인 필요: 계정 소유자]`
4. 사람에게 확인: 1차 담당 학생에게 어떤 도구로 만들었는지 서면(메신저 캡처 가능)으로 확인합니다. `[확인 필요: 의뢰인이 연락]`
5. Drive의 음성 zip(1차 참고 자료)과 저장소 mp3가 같은 파일인지 해시로 비교합니다.

**판정과 조치**

| 확인 결과 | 조치 |
|---|---|
| gTTS, 또는 확인 불가 | **다시 만듭니다.** 이용 조건이 분명한 도구로 같은 대본을 합성합니다: Google Cloud TTS(이미 코드 있음), 또는 앱에서 기기 TTS로 바로 읽기 |
| Google Cloud TTS | 그대로 씁니다. 사용한 음성 이름과 날짜를 `CONTENT_NOTICE.md`에 적습니다 |
| 사람 녹음 | 녹음한 사람의 이용허락서(실연 포함)를 받습니다(L-05 양식에 실연자 항목 추가) |

- 어느 경우든 대본의 저작자 이용허락(L-05)은 따로 필요합니다. 음성은 대본을 읽은 것이므로, 대본 권리가 정리되지 않으면 음성도 배포하지 않습니다.
- 다시 만들 때 합성 입력에는 대본 텍스트만 넣고, 사용자 정보는 넣지 않습니다.
