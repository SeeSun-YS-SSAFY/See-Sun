## 2. 화면별 스크롤 판정(기본 글꼴, 자동 판정)

판정 방법: 기기 시험의 단계 사진(`shot()`)마다 `FitReport.kt`가 화면 틀(ScreenScaffold) 세로 스크롤의 남은 길이(`VerticalScrollAxisRange.maxValue`, 지연 목록 제외)와 화면 밖으로 잘린 버튼을 기록한다. 이제 기본 글꼴에서 넘치면 시험이 실패한다(게이트). "키보드" = 화면 키보드가 열린 상태(키보드가 화면 절반을 가려 스크롤 허용, 판정 제외). "—" = 그 시점에 없던 사진(전: 수정 전 시험은 415×900에서 연령 확인 다음 단계에서 멈춰 이후 사진 없음 — §3-11).

요약(기본 글꼴 1.0, 사진 기준):

| 해상도 | 수정 전 맞음 | 수정 후 맞음 | 수정 후 넘침(허용) |
|---|---|---|---|
| 415×900(소유자 폰) | 26 / 53 | **74 / 75** | 오픈소스 라이선스 전문(읽기 화면) |
| 360×740 | 20 / 72 | **71 / 75** | 약관 [자세히] 개인정보 전문(+104dp, 읽기 화면), 라이선스 전문, 키보드 열린 입력 2 |

수정 전 360×740의 옛 동의 화면 5장: 서비스 안내 +134, 이용약관 +219, 개인정보 +245, 국외이전 +449, 민감정보 음성 확인 +691dp.

실제 앱 확인(uiautomator `scrollable` 노드 수, 소유자 폰 설정): 메인 0, 운동 재생 0, 전화번호(힌트 결과) 0. 글꼴 200%·가로 회전에서는 1(스크롤 유지, 잘림 없음).
