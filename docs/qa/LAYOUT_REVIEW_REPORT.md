## 5. 적용한 기준(요약, 근거는 11 문서 §10)

1. 위 "보는 영역"(헤더 64dp·본문) / 아래 "누르는 영역"(하단 행동). 주요 버튼 중심 화면 높이 60% 아래 — One UI viewing/interaction area, Android layout basics "reachable area", 토스 BottomCTA. Hoober 2017(가운데 선호)은 반대 근거로 적고 전체 폭 큰 버튼으로 절충.
2. 본문이 넘치면 하단 행동은 고정하지 않고 본문 끝에(WCAG 1.4.10 리플로).
3. 폭 600dp 미만 여백 16dp, 이상 24dp, 본문 열 최대 600dp — M3 breakpoints·Android 큰 화면 Tier 2("Buttons are not full width")·M3 40–60자·WCAG 1.4.8.
4. 버튼 높이 56dp↑·터치 48dp↑·간격 12dp(작은 화면 8dp) — M3 버튼 토큰·Android 접근성.
5. 버튼 레이블 한 줄, 반 폭에 안 들어가면 세로(M3 "Don't wrap label text", Apple stacked layout, KRDS 세로 배치). 보조 버튼 쌍·메뉴 타일만 어절 단위 2줄.
6. 한국어 어절 단위 줄바꿈: `LineBreak.Heading`/Paragraph+`WordBreak.Phrase` + `localeList ko-KR`, API 26–32는 `keepAllCompat`(Compose 기본은 Simple이라 명시 필요 — androidx 소스, Android 15 LineBreakConfig).
7. 최소 글자 18sp(KRDS 본문 16px 기준보다 크게), 제목 28·버튼 24/20·본문 20sp.
8. 화면당 주요(노랑) 버튼 하나, 세로 배치는 중요도 순 위→아래(M3 filled 하나·KRDS).

## 6. 남은 한계·결정 필요

1. **[결정] 작은 폰(360×640)에서 하단 행동을 고정할지**: 지금은 본문이 넘치면 행동이 본문 끝으로 가서 스크롤해야 보인다(큰 글꼴 사용자를 위한 리플로 규칙). 기본 글꼴일 때만 화면 아래에 고정하는 방법(토스 `fixedAboveKeyboard`형)도 가능 — 본문 칸이 줄어드는 대가.
2. **[결정] 내용이 적은 화면의 가운데 빈 공간**(메인·운동 첫 화면): 지금은 기준대로 빈 공간을 가운데에 둔다. 메뉴 타일을 키워 채우는 안이 있다(저시력에는 더 큰 터치 영역).
3. 넓은 화면(≥840dp)은 한 열 600dp. 2단(목록-상세) 배치는 화면별 설계가 필요해 하지 않았다.
4. 글꼴 200%에서 한 어절이 줄보다 긴 경우("1,613킬로칼로리(추정값)") 플랫폼이 어절 안에서 끊는다(기록만, 시험 통과).
5. API 26–32 단어 잇기 문자 대체는 단위 시험으로만 확인(시험 기기 API 36).
6. 실서버 시험의 배치 기록은 키보드 여부를 넘기지 않아 키보드가 열린 4장을 위반으로 센다(기기 시험 판정은 제외함).
7. B15·B16(시험 환경·가로 터치 주입)은 이번 범위에서 고치지 않았다.
