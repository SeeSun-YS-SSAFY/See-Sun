> 작성 2026-10-13 · 대상 브랜치 `feat/phase2-android`(W1 + W2a 온보딩·메인·마이페이지 + W2b 운동·데모 병합본, 시작 c4fb7f7 → 마지막 d39bd84)
> 요청: 이준영 CTO — 가짜 저장소가 아니라 **실제 서버에 붙은 실행 화면**으로 E2E가 되는지 증명, 실행 경우 전수 QA와 오류 추적
> 화면 사진: `<WORKDIR>\e2e-shots\integrated\`(여정 `NN_단계.png` 51장), `…\integrated\qa\`(QA 행별 사진, 원자료 `qa_results.json`)
> 매트릭스: `docs/qa/QA_MATRIX_app.md`

## 1. 결론

- **사용자 여정 전체가 실제 서버에서 통과했다.** 첫 실행 → 온보딩 → 메인 → 운동(안전 안내·한 가지 운동·루틴 휴식·주간 기록) → 마이페이지(키 수정·동의 철회·데이터 초기화) → 로그아웃·재로그인 → 회원 탈퇴까지 6단계 모두 기기 통과, **단계마다 서버 DB를 직접 확인한 27개 항목도 모두 통과**했다(탈퇴 뒤 개인정보 필드 전부 비움 포함).
- **QA 매트릭스 76행을 실서버에서 실행해 76행 통과**했다(오프라인·서버 500·시간 초과·회전·백그라운드·프로세스 종료·토큰 만료·동의 문서 변경·탈퇴 계정·TalkBack).
- 그 과정에서 **결함 10건을 찾아 10건 고쳤다**(남은 결함 0, 낮은 관찰 2건은 §7). 병합 때문에 생긴 것이 3건(BUG-01·02·04), 그중 BUG-02는 **로그아웃·탈퇴 뒤에도 운동 기록이 기기에 남아 다음 로그인 계정으로 올라갈 수 있는 개인정보 결함**이었다.
- 두 Room DB는 **하나로 합쳤다**(앱 DB v3, 자동 이주 2→3 + 데모 APK #1의 옛 운동 파일 자동 옮기기, 이주 시험 4건).

## 8. 알려진 한계

- 에뮬레이터 한 대(Android 16)에서만 돌렸다. 실기기·다른 OS 버전·제조사 TalkBack은 확인하지 않았다.
- **음성 인식**: 에뮬레이터에 한국어 인식기가 없어 실제 음성 입력·음성 동의(`method=VOICE` 서버 기록)는 실서버에서 못 돌렸다. 해석·재확인 흐름은 기능 기기 시험(대본 인식기)이 덮는다.
- **인증**: 가짜 Firebase(앱 FakeAuthProvider + 서버 가짜 검증기). 실제 SMS·reCAPTCHA·Firebase 계정 삭제(최대 180일)는 범위 밖.
- **오디오**: `-no-audio`라 안내 음성 실제 출력, 이어폰 버튼, 전화 수신 시 멈춤, 화면 꺼짐 재생은 확인하지 못했다(데모 안내 §4 #5~7 실기기 항목).
- **TalkBack**: 켠 상태의 접근성 검사(ATF)·자동 재생 금지·전문 펼침까지. 사람이 스와이프·두 번 탭으로 끝까지 쓰는 시험은 아니다.
- **서버**: 로컬 SQLite·DEBUG(운영은 PostgreSQL). 5xx·시간 초과는 프록시 주입(운영 Django의 HTML 500 본문을 흉내), 실제 서버를 멈춘 경우는 연결 끊김(`reset`)과 같은 앱 경로로 확인했다.
- 백업 14일 보존·자정/주 경계 날짜 처리·식단(W3)은 대상 밖이다.
