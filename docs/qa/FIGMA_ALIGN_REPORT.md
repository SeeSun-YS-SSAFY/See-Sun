## 0. 2차(같은 날 오후) — 작은 폰 분리·글꼴 시험

소유자 지시(원문): "작은 폰 처리는 별도로 하는게 좋을거같아 / figma 글꼴 사용조건 검색해서 확인해보고 최대한 유사하게 진행해줘, 만약 사용가능하면 사용해서 완전하게 똑같이 해주는게 좋을거같아", 이어서 "앱 기준으로 전이 더 나은거 같아"(msg 690).

1. **배치 단계 둘**(`LayoutTier`, `ScreenScaffold`가 정함). 기준은 앱이 쓸 수 있는 높이 = 창 높이 − 상태·내비게이션 막대(키보드는 빼지 않아 입력 중에도 단계가 바뀌지 않음).

| 단계 | 경계 | 기기 예 | 배치 |
|---|---|---|---|
| 보통 폰 `REGULAR` | ≥ 780dp | **소유자 Galaxy A55 1080×2340 @416dpi ≈ 415×900dp**(제스처 내비, 상태바 34dp → 약 866dp), 412×915(3버튼 내비 → 약 843dp), 480×1000, 접는 폰 펼침 | **Figma 수치 그대로**: 헤더 위 36dp(「탑바–타이틀 36」 필수), 묶음 사이 24dp(필수), 버튼 74dp, 마이크 188dp, 메인 타일 210dp·간격 가로 18·세로 16, 여백 20 |
| 작은 폰 `COMPACT` | < 780dp | 360×740(약 668dp), 360×640(약 568dp), 가로 화면 | 요소는 모두 그대로, 헤더 위 4·묶음 사이 8·버튼 64·마이크 112~140·메인 타일 96~210(남는 높이)·헤더 줄 60. 최소값(터치 48dp·글자 18sp·간격 8dp)은 지킴 |

   - 경계 780dp를 정한 방법: 412×915(쓸 수 있는 높이 약 843dp) 매트릭스에서 Figma 그대로 배치한 화면들의 남는 높이를 쟀다. 목록 높이가 화면에 맞춰 늘고 주는 화면(운동 목록·알레르기)을 빼면 가장 빠듯한 화면은 메인 + 「준비 중」 안내(남는 높이 66dp → 필요 약 776dp)라 780dp로 정했다(`SeeSunDimens.RegularMinHeight`).
   - 요소가 많은 Figma 밖 화면(약관 동의·운동 재생·오류 안내 + [다시 시도]가 뜬 입력)은 보통 폰에서도 묶음 사이 12dp(`dense`), 오류 상태에서는 마이크 140dp.
   - 글꼴을 키우면(1.3·2.0) 어느 단계든 본문이 스크롤된다(WCAG 1.4.4·1.4.10, 잘림 없음).
2. **글꼴**: 코디 UD 온고딕 사용 조건 확인(한국장애인개발원 https://www.koddi.or.kr/ud/sub1_2 — 상업·비상업 디자인·2차 저작물 무료, 글꼴 파일 자체의 판매·유료 배포 금지, 글꼴 데이터·디자인 변경 제한 / 산돌 표: 임베딩 허용). 공식 TTF.zip(sha256 `f72bc26c…3387`)의 Regular·Bold·ExtraBold를 **고치지 않고** 넣어(파일 이름만 Android 리소스 규칙으로) Figma 캡처와 글자 모양을 겹쳐 굵기를 맞췄다(제목·버튼·선택지 Regular, 음성 질문 ExtraBold — Figma 글꼴이 코디 UD 온고딕임을 확인). **소유자가 전/후 캡처를 보고 「앱 기준으로 전이 더 나은거 같아」라고 판단해 되돌렸다**: 시스템 글꼴(굵게)·1차 굵기·크기 유지, TTF와 오픈소스 화면의 코디 고지 제거(커밋 `44caea2`). 시험 커밋 `be6cfaf`는 기록으로 남아 있다(푸시 전이라 필요하면 정리 가능).
3. 글꼴과 상관없이 남긴 2차 변경: 설명 없는 선택지 글자 가운데 정렬(Figma 「당뇨」), 버튼·선택지 글자가 한 줄에 안 들어가면 한 번만 26sp로(`OneLineText`), 오류 안내 아래 [다시 시도] 56dp, 오픈소스 화면에 아이콘(Material Symbols, Apache 2.0)·로고 둘레 글자 모양(Pretendard, OFL) 고지.
